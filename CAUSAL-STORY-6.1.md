# Причинная история · 6.1

История развивается из изменений мира, доступных герою знаний, поступков и отношений. Для этого добавлен локальный процедурный режиссёр `causal-story.js`; он работает в автономном HTML без сети, API-ключей и новых зависимостей.

Это первая реализация генерации через правила и текстовые заготовки. Начальный материал воспоминания один раз выбирается из допустимых опор текущего мира. Последующие дела и возможности возникают из фактических событий. Система не является генеративной языковой моделью и не обещает бесконечное произвольное содержание.

## Модель

`world.causality.nodes` хранит узлы причинного графа: идентификатор, правило, ход, участников/предметы, краткое описание и ссылки `causes` на уже существующие причины. `world.causality.threads` хранит открытые, завершённые и изменившиеся дела; у результата есть ссылка на узел, который его обосновывает.

Пример возникающей цепочки:

```text
осмотр реального повреждённого предмета
  → обнаруженная потребность в ремонте
  → выполненный ремонт и подтверждённое изменение предмета
  → наблюдение или признание результата владельцем
  → возможность обсудить ответную помощь
  → фактический заём доступного инструмента
  → обязательство вернуть этот инструмент
  → возврат и признанное выполнение обязательства
```

Другой путь:

```text
выполненная работа
  → реальная рекомендация в инвентаре
  → предъявление рекомендации другому человеку
  → изменение условий торговли или признание подтверждения
  → новая возможность, связанная с известной герою историей
```

Правила связывают идентификаторы существующих предметов и NPC. Замена владельца, предмета, доступных ресурсов или исхода меняет получившийся эпизод. Ожидание, неудачная команда и простая запись желания не создают выполненный ремонт или заслуженную рекомендацию.

## Правила последствий

| Событие/условие | Что может возникнуть |
| --- | --- |
| Обнаружена настоящая поломка известного предмета | Открытое дело с конкретным предметом и владельцем |
| Предмет восстановлен | Завершение потребности, связанное с действием и изменением состояния |
| Владелец наблюдал или признал восстановление | Возможность ответной помощи в пределах его доступных вещей |
| Вещь разрушена вместо ремонта | Прежний способ завершения больше недоступен; сохраняется причина изменения дела |
| Получен заём | Обязательство возврата той же вещи |
| Заём действительно возвращён | Закрытие обязательства с сохранением истории |
| Известен конфликт | Возможности исправить конкретные последствия |
| Возврат и извинение признаны | Закрытие требования возмещения; память об отношениях сохраняется |
| Работа завершена и рекомендация действительно выдана | Возможность использовать подтверждённую репутацию |
| Рекомендация предъявлена | Изменившиеся условия торговли или подтверждение свидетелю |
| Воспоминание просмотрено из доступного источника | Основание для информированного решения |
| Решение принято | Различающиеся последствия и новая нить |
| Свидетель получил достаточное подтверждение | Признание истории с причиной, связанной с источником и поступком |
| После отказа от записи выбрана новая проверяемая цель | Продолжение истории из осознанного нового замысла |

Один и тот же завершённый результат не создаётся повторно от осмотра. Узлы ссылаются на существующие более ранние причины. Чтение списка возможностей не меняет мир. Предложения сами не исполняют физические действия и не раскрывают содержимое скрытых источников.

## Старт и воспоминание

Для стандартной истории источник получает стабильный эпизод, связанный с существующим свидетелем, местом и письмом. Пользователь может обсудить возвращение памяти обычными словами, получить разрешение, посмотреть запись рядом с хранителем или приобрести флакон при достаточных средствах.

Содержимое предъявляется до решения. Предпросмотр, доступ к источнику и разрешение на решение проверяются отдельно. Общий `stage` больше не разрешает выбор автоматически. Отпущенную запись нельзя восстановить простым повтором команды. Сохранённая запись ведёт к конкретному свидетелю; новая проверяемая цель может продолжить ветку отказа от прошлого.

Авторские тексты и канон сохраняют приоритет. В мирах без соответствующего источника модуль не создаёт флакон из одного желания игрока. Начальные опоры выбираются детерминированно и сохраняются; загрузка не меняет свидетеля или содержание.

## Сохранения

Схема основного сохранения и ключ localStorage сохранены. Новый граф добавляется при восстановлении. Стабильные опоры не пересоздаются, приобретённый товар не появляется на рынке повторно. Для старых миров добавляются отсутствующие предметы нового содержимого один раз. Физически возвращённая владельцу вещь с подтверждённой историей не остаётся невозможным требованием возврата.

Граф начинается с зафиксированного состояния миграции; неизвестные причины старых событий не выдумываются. Старое решение о памяти сохраняется: миграция не возвращает отпущенную запись. Старые исторические сообщения продолжают использовать собственные снимки упоминаний.

## Проверки

`test/causal-story.test.js` проверяет намерения и последствия, включая контрфактические варианты: без ремонта нет положительного результата; вопросы и намерения не принимают решение; установка штифта ещё не означает исправный механизм; новый конфликт блокирует старое предложение помощи. Проверяются причинные ссылки, загрузка, отсутствие повторного создания результатов и применение правил к другим владельцам и предметам.

`test/causal_story_ui.py` проверяет исходное приложение и автономную сборку: конфликт и возврат, обе ветки памяти, выбор действий из интерфейса, полный ремонт, репутацию, торговлю, чтение и встречу со свидетелем. Прежние браузерные и мобильные проверки сохранены.

```sh
npm run build
npm test

npm run test:story
```

Это проверяет работоспособность и причинность. Оценка эмоционального интереса и понятности для новых людей по-прежнему требует наблюдаемых пользовательских сессий.
