# Между строк — версия 3

[Играть в браузере](https://gdrclm.github.io/Chat/) или открыть **play.html** локально. Установки, аккаунты, API-ключи, модели и сервер не нужны. Готовый HTML содержит интерфейс, стили и движок. Для открытия сайта нужен интернет; скопированный play.html работает без него.

## Что изменилось

Вместо единственной цепочки с ключом используются предметы и их владельцы, места, цели персонажа, факты, обещания, отношения, риск и сюжетные зацепки. Отрицания, составные действия, планы и цитируемые слова разбираются отдельно. Вводные можно менять без удаления переписки. Подход и источники описаны в [NARRATIVE.md](NARRATIVE.md).

Это сценарная система, не аналог языковой модели Character AI. Она распознаёт семейства действий, комбинирует написанные реплики с результатами симуляции и просит уточнения при недостатке информации. Базовый каталог русских слов и типов вещей конечен. Новые предметы и правила надёжнее задавать явно.

## Попробуйте

- «Меня зовут Алекс. Хочу найти брата» — память имени и цели.
- «Осматриваюсь, затем беру письмо и открываю его» — связанный ход и ссылка на предмет.
- «Не беру ключ, а танцую чечётку» — отказ и неожиданный социальный ход.
- «А что если я ударю тебя?» — вопрос о возможности без самого нападения.
- «Отдаю компас», затем «Помнишь меня?» — смена владельца и память поступка.
- «У меня есть нож», затем «Использую нож чтобы поддеть запор ларца» — другой способ с последствиями.
- «Рядом лежит камертон», затем «Беру камертон» — новый авторский предмет.
- «Запомни: мою кошку зовут Луна», затем позже «Помнишь кошку?» — сохранённый факт.

Исходная сцена использует жанровую заготовку. Для собственной истории откройте «Настройки» и заполните мир, персонажа, героя и при необходимости «Опоры истории». Опоры вида `Место: кухня`, `Предметы: ложка, чашка`, `Цель персонажа: приготовить ужин`, `Правила: магии нет` имеют приоритет над стандартными декорациями. Полный список полей и пример собственной сцены находятся в NARRATIVE.md.

## Телефон и сохранение

Чат занимает один экран; прокручивается только переписка. Настройки и память находятся на отдельном экране. Высота интерфейса подстраивается под Visual Viewport. Проверены пять размеров Chromium и сценарий работы через мобильный DOM; реальная клавиатура и особенности браузера телефона требуют проверки на устройстве.

Игра сохраняется в localStorage этого браузера и адреса. В локальных файлах браузер может ограничить сохранение. Используйте «Скачать сохранение» и «Загрузить сохранение» для резервной копии и переноса. Старые сохранения мигрируют автоматически. Обновление вводных сохраняет переписку; «Начать заново» очищает её после подтверждения.

Предпросмотры вложений могут запрещать JavaScript. Открывайте игру по ссылке в браузере или открывайте play.html полноценным браузером, а не внутри предпросмотра мессенджера.

## Для разработчика

Node.js 22.8+ нужен только для разработки. Сторонних npm-зависимостей нет.

- `npm test` — проверки поведения и автономного файла.
- `npm run build` — пересобрать play.html после изменения исходников.
- `npm run build:pages` — создать dist/index.html, dist/play.html и .nojekyll.
- `npm start` — необязательный локальный сервер разработки.
- `python3 test/mobile.py` и `python3 test/ui.py` — браузерные проверки с Playwright и системным Chromium.

Исходники находятся в main, готовый сайт — в gh-pages, источник GitHub Pages: Deploy from a branch → gh-pages → / (root). После успешной сборки и тестов публикуйте содержимое dist/ в gh-pages. На хостинг не требуются Node.js и серверное приложение.
